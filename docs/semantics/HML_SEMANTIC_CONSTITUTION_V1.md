# HML Semantic Constitution v1

**Status: constitution and backlog. Not a compiler sprint.** Nothing here licenses new
implementation. It fixes vocabulary so that later claims about HML can be stated precisely,
and records which judgments the current instrument actually establishes.

Written 2026-08-08, before any HML has ever been shown to a model.

---

## 1. The judgment classes are separate

The single most consequential error available to this project is collapsing these into one
`VALID` flag. They are different questions with different evidence and different failure
modes.

| judgment | question | who decides | status in HML today |
|---|---|---|---|
| **A. PARSES** | is it in the grammar? | `parser/` | enforced |
| **B. TYPECHECKS** | do names resolve and types agree? | `type_system/` | enforced |
| **C. HAS_DEFINED_DENOTATION** | does every term denote? | `reasoning/partiality.py` (D-044) | **partial** — definedness is a property of terms; the guard is narrow and fails closed |
| **D. IS_SEMANTICALLY_EQUIVALENT** | do two forms denote the same object? | `backends/canonical.py` content hash | enforced structurally, not up to mathematical identity |
| **E. IS_ENTAILED** | does Γ license this conclusion? | `reasoning/check.py` + the 16-rule kernel | enforced for the implemented rules only |
| **F. EXECUTES** | does it run, and to what? | — | **absent.** HML has no evaluation semantics |
| **G. IS_PROVEN** | is there a checked derivation? | `DeriveStmt.status`, computed never asserted | enforced for the implemented rules only |

Two consequences already load-bearing in this codebase:

- **A ∧ B does not give C.** The D-044 exploit reached VERIFIED/PROVED through
  `multiply_both_sides(by := 1.0 / 0.0)`: it parsed, it typechecked, and it denoted nothing.
- **G is not assertable.** `DeriveStmt.status` has no surface syntax. A model may claim a
  derivation; it may not claim the derivation is correct. That asymmetry is the point.

## 2. Denotational meaning — what a construct denotes

For the fragment the arena uses:

| construct | denotes |
|---|---|
| `var x : Real` | a name bound to an element of ℚ (the generator emits only exact rationals) |
| `var P : Proposition` | a name bound to an element of {⊤, ⊥} |
| `def D : Set[Real] := {x : Real \| φ}` | the subset of ℝ satisfying φ; used to relativise binders |
| `def R(x, y) : Proposition := ψ` | a total binary predicate, given by ψ's extension |
| `assume ℓ : φ` | φ is added to Γ under label ℓ; ℓ is *addressing*, not content |
| `goal ℓ : φ` | φ is placed in question. **Stating a goal never asserts it** — `hml check` reports OPEN whether φ is true or false, so a goal cannot leak an answer |
| `t₁ = t₂` | equality of denotations. **Not** `~` (distributed as), **not** approximation |
| `φ implies ψ` | material implication, *ordered*. **Not** correlation, **not** causation |
| `forall x : Real . x in D implies φ` | relativised universal. HML has no `forall x in D` binder; the domain guard is part of the formula |
| `exists x : Real . x in D and φ` | relativised existential |

**Binder order is denotational, not notational.** `∀x∃y R(x,y)` and `∃y∀x R(x,y)` denote
different propositions and disagree on most finite relations. `examples/logic/` exists for
this, their canonical hashes differ, and the arena's headline contrast is built on it.

**A known gap, recorded not fixed: HML has no uninterpreted predicate.** A declared
`Predicate` is not callable (`HML-T470`), and the only callable form requires a body. So a
finite relation can only be given in closed form. This is why all three arena arms state a
relation once in their own idiom rather than by per-tuple enumeration.

## 3. Operational meaning — legal transitions

A reasoning state is `S = ⟨Γ, G, E⟩`: assumptions in scope, goals, and the evidence DAG.
An action `a` is a rule application. `S_t --a_t--> S_{t+1}` is legal exactly when:

1. `a` names a rule in the 16-rule trusted kernel — an inference without a named rule is an
   assertion, not a derivation, and HML has no syntax for "this follows somehow";
2. every premise is **ESTABLISHED** in `Γ_t`. A `goal` is not admissible as a premise
   (D-027 closed the hole where `goal g1 : 1.0 = 2.0` could prove itself);
3. the rule's own shape check passes — `apply` computes the conclusion from the premises and
   **must not look at the author's claimed conclusion**;
4. mandatory obligations generated by `a` are discharged or the step is not VERIFIED;
5. scope discipline holds (D-043): facts do not survive their `scope`, precede it, cross to
   siblings, or escape nesting.

`S_{t+1}` differs from `S_t` only by the conclusion the kernel licensed and the obligations
it generated. **The arena's Endpoint B exercises none of this** — its worlds carry
declarations and assumptions only. The transition relation is the subject of the
*next-action* endpoint, which is where §3 becomes measurable.

## 4. Proof/axiomatic meaning — what Γ licenses

`Γ ⊢ φ` holds when there is a finite chain of legal transitions from `Γ` to `φ`, every step
kernel-checked, every mandatory obligation discharged. Three standing constraints:

- **Rejection is the product.** Unresolved names, invalid scopes and incompatible types are
  refused. A permissive checker has no value here.
- **The prohibited conflations are type-level, not conventional.** `Distribution[T]` is not a
  `T`; `RandomVariable[T]` is neither; `=` is not `~`; `=>` is not correlation;
  `Probability` and `PositiveReal` are incomparable, meeting at `NonNegativeReal`.
- **Backends must report loss.** A backend that silently omits a construct produces
  authoritative-looking output that is wrong — the worst failure mode available here.

## 5. What the arena instrument establishes today

Audited offline in `tests/arena/test_semantic_audit.py`, **62 checks, all passing**, over
three families × three arms. Read-only: no production code and no model-visible prompt,
difficulty, scoring rule or task semantics was changed, because changing any of those after
model selection would invalidate the selection.

| property | enforced? | by what |
|---|---|---|
| PARSES (HML arm) | yes | real compiler, per world |
| TYPECHECKS (HML arm) | yes | real compiler, separate check from parsing |
| HAS_DEFINED_DENOTATION | yes, vacuously | no division is generated, so no term can be undefined |
| entities and stable identities | yes | decl names + fact labels round-trip in all arms |
| types | yes | `(name, sort)` round-trips in all arms |
| free vs bound variables | yes | `BVar` and `Elem` stay distinct through every decoder |
| **binder order and scope** | yes | nesting round-trips; plus a negative control that a swap is *observable* in each arm |
| assumptions | yes | `(label, canonical(prop))` sets round-trip |
| **implication direction** | yes | `A implies B` never decodes as its converse |
| goal / query | yes | kind, target and claim round-trip |
| oracle answer | yes | one item, one key — literally shared, with three distinct prompts |
| whole-world identity | yes | 1800/1800 round trips, re-asserted rather than replaced |
| EXECUTES | **n/a** | the arena has no evaluation semantics |
| IS_PROVEN / obligations | **n/a for Endpoint B** | asserted: no pilot item contains `derive` or `proved` |

No missing invariant was found, so **no new tests beyond this audit were added and no
production code was touched.**

## 6. Deferred — recorded, not built

These need representation-level evidence first and are explicitly out of scope:

ambiguity-reading sets · proof + countermodel parallel search · semantic equivalence-class
voting · Tree/Graph-of-Thought controllers · Lakatos discovery mode · conjecture revision ·
concept invention and versioning · large ontology expansion · a custom HML-trained policy ·
token-compression redesign.

The one queued endpoint, not to be run until Endpoint B is preserved, is small-step
operational reasoning `S_t --a_t--> S_{t+1}` — next-action prediction, which is the direct
test of §3 and the reason §3 is written down now.
